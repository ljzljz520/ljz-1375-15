# 方言词典审校与检索系统

纯 Python 标准库实现（sqlite3 + http.server + unittest），无第三方依赖。
**完整词库只存在于服务端 SQLite**，前端页面全部通过 REST API 取数，不持有任何静态词表数组。

## 运行

```bash
cd dialect_dict_app
python3 run.py            # 公开页 http://127.0.0.1:8000/  后台 /admin
python3 -m unittest discover -s tests -v   # 12 项验收测试
```

演示账号（仅演示用令牌）：编辑 `tok-editor` / 审校 `tok-approver`。

## 架构

```
dialect_dict/
  db.py           SQLite 模式：词条/版本/标音/义项/例句/关系边/来源/地区/音频/文章引用/发布物/索引任务/审计
  normalize.py    规范化检索键 + 偏移映射（可解释高亮的基础）
  romanization.py 标音方案转换表；不可无损转换即 unconverted
  services.py     业务逻辑：身份、合并/拆分、工作流、引用、授权
  publish.py      版本化关系闭包 + (词条,版本) 键缓存
  indexer.py      异步索引服务（版本守卫，容忍乱序完成）
  search.py       规范化键 + 原文分字段双索引检索
  api.py          HTTP 层（角色在路由与服务层双重校验）
static/           public.html（公开检索） admin.html（审校后台）
tests/            验收测试
```

## 词条身份：不靠拼音

词条身份是不透明 id（`e_xxx`）。同音多义各自成条（如「芳 fong1 / 方 fong1」），
拼音只用于 `GET /api/entries/{id}/homophone-candidates` **提示候选**，
关联必须由编辑显式建立关系边：

| 现象 | 建模 |
|---|---|
| 同音多义 | 独立词条 + `homophone` 边 |
| 异体字 | 独立词条 + `variant_char` 边（渠→佢），公开页显示"见主词条" |
| 地区异义/异称 | 义项挂 `region_id` + 词条间 `regional_variant` 边（雪櫃↔冰箱） |

**合并再拆分**：`merge` 把义项/标音/关系边迁入目标并留墓碑（旧深链接返回重定向），
全部移动写入 `move_events`；`split` 带 `restore_entry_id` 时复活墓碑并按
`move_events` 精确还原标音与关系边。

## 标音方案切换

- 原始记录（`origin='recorded'`）**永不修改**；转换结果另存新行并 `converted_from` 指回。
- 转换按显式音节表逐音节映射；**任一音节无映射即整条 `unconverted`（text=NULL）**，
  展示层回退到原始记录并标注"未转换"——绝不猜读。
- `GET /api/public/entries/{id}/pron?scheme=yale` 演示该回退。

## 规范化检索键 vs 原文分字段索引

每个字段文档同时存两份键（`index_docs` 表）：

| | 原文分字段索引 (`mode=raw`) | 规范化检索键 (`mode=norm`) |
|---|---|---|
| 键 | 字段原文 | 逐字符折叠后的键 |
| 匹配 | 精确子串 | 折叠后子串 |
| 优点 | 零歧义，适合引文核对 | 高召回 |
| 例 | 查"龙舟"只命中简体**译文**字段 | 查"龙舟"命中繁体词形"龍舟" |

规范化流水线（每步记录 flag，供解释）：**简繁折叠**（内置演示字表，生产换 OpenCC）→
NFKD 分解 → **音标组合字符折叠**（丢弃 Mn 类：`a+U+0304→a`，预组合 `ā` 同样命中 `ma`）→
**标点忽略**（P* 类）→ 空白忽略 → casefold。

**可解释高亮**：规范化时记录 `offsets[i]=(原文起,止)`，命中区间映射回原文坐标；
结果携带 `via`（exact/normalized）、`folds` 与中文 `explanation`
（如"规范化匹配（标点忽略、简繁折叠）"），前端据此 `<mark>` 高亮并说明原因。
`GET /api/public/search/compare?q=` 并排对比两种键的命中差异。

## 版本化发布、引用与缓存

- 发布 = 把 词条+标音+义项+例句+一跳关系边 冻结为**不可变闭包**，按 `(entry,version)` 存 `publications`。
- 旧深链接 `?v=N` 永远取到旧版；`GET /api/public/entries/{id}/versions` 列出版。
- **缓存键 = (entry, version)**：不同版本的解释与例句物理隔离，
  "旧解释配新例句"在结构上不可能（验收测试 6 逐版本断言配对一致）。
- 文章按 `(sense_id, sense_version)` **固化引用**：义项被修改甚至被删除，
  文章仍解析到引用时版本；删除为软删除，`/api/public/senses/{id}` 提供存档视图与删除说明。

## 异步索引与乱序完成

发布即向 `index_tasks` 投递 `(entry, version)`。worker（后台线程/测试手动）完成任务的
**顺序任意**：仅当 `task.version > 该词条已应用版本` 才应用，否则标记 `superseded`。
因此 v1..v3 无论按何种顺序完成，索引都收敛到 v3（验收测试 4 覆盖两种乱序）。

## 音频撤权与无音频文本

音频**内容是版本化的**（随闭包发布），**授权是实时策略**：撤权（仅审校）后，
serve 时在闭包副本上叠加当前授权状态——摘掉音频 URL、保留文本转写并标 `audio_revoked`，
公开页立即改显"音频已撤权，提供文本：…"，且缓存原件不被污染。

## 角色分离与尊重性语境

- `editor`：建/改词条、标音、义项、例句、关系边、合并拆分、提交审核；
  **不能**批准/发布/撤权（403）。
- `approver`：批准、发布、音频撤权、查看审计；**不能**编辑内容（403）。
- 每个义项可挂 `usage_note`（尊重性语境说明），公开页显著展示；
  全站横幅 + 每条发布物均附 `respect_notice`；无音频/撤权时一律提供文本。

## 已知边界（演示取舍）

- 简繁表与标音转换表为内置小子集，生产应替换为 OpenCC / 完整音节表。
- 检索为全表扫描 + 子串匹配，演示规模足够；大规模可换 FTS5 而保留双键设计与偏移映射。
- 令牌为演示明文；生产应换签名令牌 + HTTPS。
